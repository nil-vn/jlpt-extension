# Desktop Phase 1 — Milestone 0 Spike

Phase 1 bootstraps the desktop runtime so the migration can proceed incrementally from this feature branch.

## Pinned toolchain

| Tool | Version |
| --- | --- |
| Go | `1.25.1` |
| Wails CLI/module | `v3.0.0-alpha.93` |
| Node.js | `24.15.0` |
| Svelte | `5.55.7` |
| Vite | `8.0.13` |

## What is included

- `app/`: Wails v3 desktop skeleton with Go backend and Svelte 5 frontend.
- `app/appservice.go`: simple Go service exposed through Wails bindings.
- `app/frontend/bindings/`: generated TypeScript bindings committed for deterministic frontend imports.
- `.github/workflows/desktop.yml`: CI bootstrap that installs Wails/Linux dependencies, generates bindings, checks/builds Svelte, runs Go tests, builds a Wails dev binary, and smoke-starts `wails3 dev` under Xvfb.


## Build asset policy

The repository intentionally tracks only the Wails project files required to build:

- `app/build/config.yml`
- Wails `Taskfile.yml` files under `app/` and `app/build/**/Taskfile.yml`

Generated platform assets under `app/build/` (for example `.desktop`, `Info.plist`, Dockerfiles, AppImage/nfpm/MSIX/NSIS files) are ignored and regenerated by Wails tasks during local builds or CI. Do not commit generated build outputs unless a future packaging milestone explicitly requires a reviewed source asset.

## Local commands

```bash
cd app
export PATH="$PATH:$(go env GOPATH)/bin"
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-alpha.93
cd frontend && npm ci && cd ..
wails3 generate bindings -ts -clean=true
wails3 build DEV=true
wails3 dev -config ./build/config.yml -port 9245
```

On Linux, install Wails desktop dependencies first:

```bash
sudo apt-get install -y build-essential pkg-config libgtk-4-dev libwebkitgtk-6.0-dev
```

In headless CI, `wails3 dev` needs Xvfb and WebKit sandbox overrides because the app opens a native WebView.
